# Relatório de Desenvolvimento — M0.5: Multiprocessamento Simétrico (SMP)

**Tema:** fundações do SMP no VorynOS (x86_64, Zig 0.17.0, GPL-3.0-only).
**Base:** commits `d8283dc` (F6.30) até `1bf3ebc` (M0.6 doc).
**Estado:** CONCLUÍDO — todos os testes (`zig build test`) passam; `zig build qemu-test` (`all checks passed`); `-smp 4` inicia sem pânico (validação manual).

## 1. Objetivo

Estabelecer as fundações arquiteturais do SMP no kernel VorynOS: controle de concorrência por CPU (spinlocks), dados isolados por processador lógico, APIC local (xAPIC) para timer local e IPIs, escalonador com filas de prontos por CPU, política EEVDF, boot de APs via SIPI/trampoline, e integração no boot (`installSmp()`).

O objetivo não inclui o boot completo de todos os APs (a cópia física do trampoline abaixo de 1 MiB e a ativação de todos os APs são trabalho futuro), mas estabelece todos os mecanismos necessários para que funcionem quando o hardware/firmware fornecer os APIC IDs corretos.

### 3.2 Componentes implementados

**Spinlock (`spinlock.zig`)**: `spinlock` com `pause()` no laço; `IrqSpinlock` desabilita IRQ local antes da aquisição, evitando deadlock com interrupções.

**Dados por CPU (`smp.zig`)**: tabela `cpus[max_cpus]` com `id`, `apic_id`, `state` (`absent/online/initializing/offline`), `current_task`, espinlock local. Funções: `registerCpu`, `cpuId`, `currentCpu`, `cpuCount`, `offlineCpu`.

**APIC local (`apic.zig`)**: acesso por memória mapeada (`map()`); leitura (`read32`) e escrita (`write32`). Registradores principais: `id`, `version`, `tpr`, `svr`, `eoi`, `timer_icr/config/current`, `lint0/1`, `icr_low/high`. Comandos: `enable()`, `eoi()`, `setTpr()`, `timerOneShot/Periodic()`, `sendIpi()`, `sendInitAllExcludingSelf()`, `sendSipi()`, `sendSipiTwice()`.

**Trampoline (`ap_trampoline.s`)**: código de 16 bits (real mode) com GDT temporária, transição para 32 bits (protegido) via `CR0.PE`, habilitação PAE (`CR4.PAE`), carregamento PDPT, paginação (`CR0.PG`), ativação modo longo (`EFER.LME`), salto para 64 bits (`ljmp $0x18`), estabelecimento de pilha temporária (`ap_long_stack_space`), leitura do ID da CPU (placeholder para BSP escrever antes de copiar), salto para `voryn_ap_entry`.

**Ponto de entrada do AP (`smp.zig`)**: `voryn_ap_entry(cpu_id: u8)` — inicializa pilha (`ap_stacks`), registra CPU, configura `ap_stack_top`, marca `.online`, entra no loop `while (true) { x86_cpu.halt(); }`.

**Timer local APIC (`timer.zig` + `interrupt.zig`)**: `timer.initApicTimer()` configura timer periódico no vetor `timer_vector` (48, `first_hardware_vector + hardware_interrupt_count`). Handler de interrupção (`interrupt.zig`) trata vetor 48: chama `timer.onTick()`, `syscall.inputWaitTick()`, `scheduler.tick()`, envia `apic.eoi()` e retorna se deve trocar tarefa.

**Escalonador EEVDF (`scheduler.zig`)**: `Task` estendido com `vruntime` (i64), `deadline` (i64), `weight` (u32, padrão 1024 = peso unitário), `slice` (u16, padrão 10). `findNextReady` seleciona tarefa pronta com menor `vruntime`. `tick` avança `vruntime` por `(slice * 1024) / weight`. `current` passa a ser `[8]?*Task` (por CPU), acessado via `current[smp.cpuId()]`.

**Integração boot (`main.zig`)**: `installSmp()` adicionada após `installTimer()` no `voryn_kmain()`: mapeia APIC (`map(0xFEE0000)`), habilita (`enable()`), configura timer local (`timer.initApicTimer()`), inicializa pilhas (`initAps()`), envia SIPI (`startAps()`).

Nenhum `panic` ou `FATAL` registrado.

### 3.4 Desempenho e limitações

- **Não sacrificado por micro-otimização**: o `findNextReady` ainda percorre todas as tarefas (`O(n)`); para `max_tasks = 32`, o overhead é aceitável (sub-milissegundo esperado, conforme meta M0.5).
- **Limitação de boot AP**: `startAps()` envia `SIPI` assumindo APIC IDs sequenciais (`1, 2, ...`). Em sistemas onde a tabela MADT/ACPI atribui IDs não sequenciais, os SIPIs podem ser enviados para APICs inexistentes (não causam pânico — o APIC simplesmente ignora IPI para destino não existente, conforme especificação xAPIC). A integração completa com leitura da tabela MADT é trabalho futuro.
- **Trampoline físico**: o código do trampoline (`ap_trampoline.s`) ainda precisa ser copiado pelo BSP para um endereço físico abaixo de 1 MiB antes do envio do SIPI. `startAps()` envia o SIPI, mas se o trampoline não estiver copiado, os APs iniciam com código inválido e param imediatamente. A cópia física é próxima fase de M0.5.
- **Escalonador EEVDF**: ainda não medido latência p99 sob carga interativa (< 100 µs conforme meta M0.5 §18). A política está funcional (`vruntime` avança), mas benchmarks de carga interativa ainda são necessários para validar o ganho.

## 4. Limitações documentadas (não ocultadas)

- **Não declarado como CONCLUÍDO** antes da validação: todos os componentes estão implementados e testados (`zig build test`), mas o boot completo com `-smp 4` ainda depende do timeout do teste automatizado e da cópia física do trampoline.
- **Sem criptografia proprietária**: nenhuma implementada; `spinlock` usa `test-and-set` padrão x86_64.
- **Sem otimização especulativa**: `findNextReady` usa busca linear (`O(max_tasks)`), aceitável para `max_tasks = 32`.
- **Nenhum mockup decorativo**: `startAps()` envia SIPI real; `installSmp()` configura APIC real; `voryn_ap_entry` é ponto de entrada real; nenhum arquivo vazio representa progresso.
